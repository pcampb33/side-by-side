# company-compare — spec

Search two US public companies, pick a lens, and get a Claude-generated comparison UI grounded in SEC filings. A portfolio showcase: public repo, live on Vercel, cheap to run, every number traceable to its filing.

Decided 2026-10-29. Each decision below was made explicitly; don't reopen one without a new reason.

## 2. Architecture

```
lib/sec/        SEC client: ticker search, companyfacts, submissions, filing text. Server-only.
lib/normalize/  companyfacts → ~15 metrics × 5 FY + derived ratios, each value carrying its source
lib/filings/    10-K text → Haiku condensation (business + risks, with verbatim quotes)
lib/cache/      one interface, two backends (fs for local, Upstash for deployed), chosen in one place
agent/          lens + mode + normalized payload → stream of component calls or HTML. No Next.js imports
evals/          fixtures (saved normalized payloads) + checks + scorecard
app/            Next.js App Router: pages, route handlers, auth, rate limits, rendering
```

Request flow for a new comparison: auth check → limit + budget check → normalized data for both (cache or SEC) → condensed 10-K (cache or Haiku; text lenses only) → agent streams → result cached under `pair|lens|mode` → spend + log recorded.

## 3. Data

**Sources** (all server-side; SEC has no CORS and requires a `User-Agent` with name + email; max 10 req/s):
- `https://www.sec.gov/files/company_tickers.json`: search index, refreshed daily.
- `https://data.sec.gov/submissions/CIK##########.json`: profile (name, tickers, exchange, SIC + description, fiscal year end, state, address) and the filing list.
- `https://data.sec.gov/api/xbrl/companyfacts/CIK##########.json`: reported financials. Several MB for large filers: never cache raw; cache the normalized result (a few KB).
- Latest 10-K primary document: for the text lenses.

**Metrics** (annual, 10-K, last 5 FY). Each metric has an ordered list of fallback XBRL tags; build and test this first:
revenue, gross profit, operating income, net income, R&D, cash, total assets, total liabilities, long-term debt, shareholders' equity, operating cash flow, capex, dividends paid, buybacks, diluted EPS, shares outstanding.

**Derived in code, never by the model:** gross/operating/net margin, YoY revenue growth, free cash flow, debt-to-equity, R&D % of revenue, cash runway where meaningful (≤10 years). *2026-10-31:* total liabilities falls back to total assets − total equity when a filer reports no liabilities line (KO), cited to both inputs.

**Missing values:** a metric with no matching tag is `not reported`, never 0 or blank, and propagates as such into derived ratios. *2026-10-31:* Ford's long-term debt stays `not reported`: its 10-Ks since FY2020 tag it only per segment (dimensional facts, which companyfacts omits), so there is no consolidated figure to cite; summing the segments was considered and declined.

**Every value carries its source:** accession number, form, fiscal year, filed date, tag used. Citations are built from this, not from the model.

**10-K text:** the filing (HTML → text) goes to Haiku 5.5 once per filing, which returns a structured summary of Item 1 (Business: segments, products, markets) and Item 1A (Risks: themed, each with verbatim quotes and section refs). Code verifies every quote appears verbatim in the filing text and drops any that don't. Cached until a newer 10-K exists.

**Cache layers:** ticker index (1 day), normalized financials (1 day), condensed 10-K (per accession number, no expiry), generated result (per `pair|lens|mode`, no expiry; Regenerate replaces it). A failed fetch is never cached as an empty result.

## 4. Generation

**Grounding rule:** the agent never writes chart or card numbers. Components take metric keys and years (e.g. `{metric: "revenue", years: "all"}`) and the renderer looks values up in the normalized payload, so charts cannot contain invented numbers and citations come for free. Numbers can only appear in model-written prose (takeaways, freeform HTML); the eval checks those against the payload.

**Component catalog** (each a tool with a zod schema):
company header (fixed, not generated), metric cards, trend line, grouped bars, ratio gauge, cost breakdown, risk themes, business overlap, takeaways (3-5 neutral differences). No radar chart (mixed units, misleading area).

**Lens guidance** lives in `agent/`: what each lens is for and which components usually serve it. The agent chooses; the lens steers. *2026-11-01:* each text component is offered only in its own lens (risk themes in Risk exposure, business overlap in Where they compete), so two lenses never show the same tiles; a risk goes in one row only.

**Freeform mode:** same payload, plus the site's color/font tokens for both themes. *2026-11-01:* visual first, minimal visible text (a one-sentence intro, at most one sentence per chart, one-sentence takeaways); longer explanations are fine in a closed `<details>` the reader can open (owner's preference). Output is one self-contained HTML document rendered via `<iframe srcdoc sandbox="allow-scripts">` (no `allow-same-origin`). *2026-10-31:* no links or per-number citations inside it; the page names its sources in text and a note under it points to Components, which cites each number. Fonts fall back to system stacks (the sandbox can't load the site's fonts).

**Model settings:** Sonnet 5.5 with streaming; effort set explicitly (start at `medium`, tune via evals). Opus 5.5 can't disable thinking and rejects forced `tool_choice`, so use `auto` + instructions (kept for Sonnet too). Check `stop_reason` for `refusal` and show an honest error, not an empty result.

## 4a. Showing the process (decided 2026-11-01 by the owner)

The site is a showcase of generative UI, so each comparison shows how it was made, without getting in the way.

- **Strip:** under every comparison, collapsed to one line: the same five steps on every page (SEC data, annual reports read, lens brief, Claude composes, checks), each with a one-line general explanation and this run's count (e.g. "6 components, 2 sent back and fixed"). Tapping a step expands this run's real trace for it.
- **Guidelines view for this comparison** (linked from the strip): what Claude was given and followed for this page: the lens brief, the components offered and the ones excluded, the grounding rules, the design tokens (and the kit pieces a freeform page used), and the full ordered trace: each tool call with its input, every call the checks sent back with their exact message, timings, model, tokens.
- **Traces are recorded per run** (tool calls, check feedback, timings, tokens, code-check results), stored with the cached result and in the featured JSON. A run without a trace (older cache) shows the general explanation only.
- **Freeform kit:** the frame provides the site's card, stat and chip styles and a chart helper that draws to scale from the data; the prompt asks Sonnet to use them; `checkPage` and the evals still apply. The trace lists which pieces a page used.
- **README:** the general breakdown (the five steps and the rules), linking to a live guidelines view.
- **Placement** *(2026-11-01, owner, mock v3 https://claude.ai/artifact/PnBMomdoskMJm1MkKKXHXR)*: one URL, `/compare/<pair>/<lens>/process` (keeps `?mode=freeform`), shown by width. **Desktop, from ~1100px:** a persistent sticky side panel (fluid, ~300-420px) beside the comparison, which takes the rest (never under ~720px); there it replaces the bottom strip and can collapse to a slim rail. The comparison's layout responds to its container, not the viewport (Tailwind container queries; Overlap already does). **Narrower desktop:** the bottom strip; tapping opens the panel over the comparison. **Phone:** tapping opens it full screen; Back closes it. **Opened from a link** (README, shared, refresh): a standalone page. In-app taps use an intercepting route so the comparison stays mounted underneath: leaving it aborts a live run (`comparison-stream.tsx` aborts its fetch on unmount and the route aborts the model run). A standalone page opened mid-run shows the general five steps and a "still generating" note; the trace exists once the run finishes.
- **Desktop panel behaviour** *(2026-11-01, owner)*: on the right, sticky under the site header, scrolls on its own; the comparison's company header stays in the left column. Starts open on every comparison; collapsing to the rail is remembered per browser. One scroll: the five steps on top (expand in place), then the guidelines view's sections below, collapsed (brief, components, grounding rules, tokens, full trace, exact prompt), so desktop needs no second surface. Live run: the active step expands and shows its trace as it happens, the previous one folds; the first tap or scroll in the panel stops the auto-follow. The rail shows five status dots that light up.
- **Step contents** *(2026-11-01, owner, mock section 2)*: SEC data: a metric × year dot grid per company, gaps marked not reported, fiscal-year windows, 10-K count. 10-Ks read: each company's themes with quote counts, dropped quotes, link to the 10-K (greyed "not needed" on number lenses). Lens brief: the brief and used/offered/excluded components. Claude composes: the call trace with send-back messages. Checks: each code check's result.
- **Live checks** *(2026-11-01, owner)*: the code checks (numbers, not reported, quotes, components) run on every live run so step 5 shows real results; a finding is shown, the page still displays.
- **Exact prompt** *(2026-11-01, owner)*: the guidelines view shows everything Claude received, as sent (system prompt and the full data payload), stored in the trace at run time so it stays true if `agent/prompt.ts` changes later. Closed by default.
- **Live strip** *(2026-11-01, owner)*: on a live generation the strip is there from the start and each step lights up as it happens (SEC data, reports read, brief, each component call including send-backs, checks). Featured pages arrive whole and show it finished.
- **One regeneration:** traces and the kit both change generation, so the featured comparisons are regenerated and reviewed by eye once, after both exist. *2026-11-01, owner:* that regeneration waits for the API key (step 11), so traces carry real token counts; login runs include ~32k tokens of Claude Code overhead per request. Until then, traces record which backend ran them.

## 5. Access, cost, and logging

- Auth.js with the Google provider, basic scopes (email, profile). Enabled by `REQUIRE_SIGN_IN=true`. If it is true and Google credentials are missing, the app refuses to start. Local clones leave it off (their own key).
- Owner bypass: `OWNER_EMAIL`, no limits.
- Per-account daily counter and monthly spend total in Redis. Over a limit: a plain message pointing to featured comparisons and to cloning the repo, never an error-looking or empty state.
- Log entries written with a 14-day TTL; privacy note in the footer.

## 7. Evals (`evals/`, `npm run eval`)

Fixtures are saved normalized payloads (+ condensed 10-Ks) for the featured pairs plus one awkward filer (a bank, e.g. JPM, with no gross profit). Free, code-only checks first:
1. Every number in prose/HTML appears in the payload (within rounding); fiscal-year labels match the payload's years. Chart axis ticks are a scale, not values, and are skipped.
2. Every component call validates against its schema; every metric key exists.
3. `not reported` metrics are never presented as values.
4. Components chosen are plausible for the lens (rule table): no text component outside its own lens, takeaways once and last, a risk in one row only.
5. Freeform HTML passes the app's own page check (no external resource loads), then renders in headless Chromium with every request blocked: any request, script error, or width over 320px is a finding. Text in closed `<details>` counts as page text.
6. Every quote of six or more words appears in the verified filing quotes.
Model-graded checks ("does this answer the lens?") only after real output has been reviewed. Prints a scorecard per lens × mode; `--model sonnet|opus` picks the model (how step 8's choice was made). Run by hand; never in CI. `npm run featured` reuses these checks: it keeps a run only when it has no findings. The checks don't judge how a page looks, so featured pages are also reviewed by eye.

## 9. Risks and verify-first items

- **R1, AI SDK coverage.** Before building the agent, confirm `@ai-sdk/anthropic` accepts `claude-opus-5-5` and passes effort (and ideally refusal fallbacks) through provider options. If it can't, keep the AI SDK for UI streaming and call `@anthropic-ai/sdk` inside `agent/`. *2026-10-29, offline:* `@ai-sdk/anthropic` 3.0.132 lists `claude-opus-5-5`, has an `effort` provider option and maps `refusal` to finish reason `content-filter`. Still to confirm with a live call once the key exists, before the first deploy. Token counts from the login backend carry ~32k tokens of Claude Code overhead per request, so R6 cost estimates must come from the API backend.
- **R2, XBRL tag variance.** The normalization layer is the real work. Test on AAPL, MSFT, NVDA, KO, F, JPM before any UI.
- **R3, 10-K extraction.** Large filings exceed 100k tokens (Haiku's higher price tier above 100k); still about a cent per filing. Quote verification is mandatory.
- **R4, Vercel function duration.** A streamed generation runs 20-40s; confirm the current Hobby max duration and set `maxDuration` on the route. *2026-10-31:* Vercel's docs (updated 2026-08-24) give Hobby with Fluid compute (default) 300s default and max. Measured: freeform 88-97s, uncached text lens 49-71s. Set `maxDuration = 300` and stream a heartbeat while the model works (HTTP/1.1 clients may close idle connections).
- **R5, Spend-limit floor.** Confirm the Anthropic console accepts a ~$6 workspace limit.
- **R6, Cost estimates are unmeasured** (~$0.15-0.40 per Opus comparison; Sonnet, chosen at step 8, is half the price per token and writes fewer tokens). The eval run records real usage; revisit the budget after it.
